# Лабораторная работа №4 — сбор и предварительная обработка веб-данных

## 1. Цель работы

Разработать систему автоматизированного сбора веб-данных с использованием **Scrapy** и **Playwright**, включающую:

- сбор новостных публикаций со статического/SSR-сайта;
- сбор товаров с динамических маркетплейсов;
- обработку и очистку полученных данных;
- удаление дубликатов;
- проверку обязательных полей;
- обработку ошибок HTTP;
- экспорт результатов в JSON и CSV;
- запуск пауков через командную строку.

Проект выполнен в виде отдельного Scrapy-приложения с двумя пауками: `NewsSpider` и `EcommerceSpider`.

---

## 2. Используемые технологии

- **Python 3.12+**
- **Scrapy**
- **scrapy-playwright**
- **Playwright**
- **ftfy** — исправление проблем с кодировками текста
- **ItemAdapter**

- **CSV / JSON** — форматы экспорта

# 5. NewsSpider

`NewsSpider` предназначен для сбора публикаций с **Habr**.

Файл:

```text
lab4_scraper/spiders/news.py
```

Источник:

```text
https://habr.com/ru/articles/
```

Паук получает:

- название статьи;
- краткое содержание;
- дату;
- URL;
- источник.

Для устойчивости к изменению HTML используются CSS-селекторы и XPath.

Заголовок статьи извлекается через XPath с `string(.)`, что позволяет получить текст из вложенных HTML-элементов.

Также реализована последовательная пагинация страниц Habr.

### Запуск

Без фильтрации по ключевым словам:

```powershell
python .\run_spider.py --spider news --max-items 110 --output .\output\news.json
```

С фильтрацией:

```powershell
python .\run_spider.py --spider news --keywords "AI,Python,данные" --days 7 --max-items 110 --output .\output\news.json
```

Параметр `--days` сохранён для совместимости с заданием и CLI.

### Результат

В приложенном результате проекта:

```text
109 записей
```

Файл:

```text
output/news.json
```

# 6. EcommerceSpider

`EcommerceSpider` предназначен для сбора товаров с динамических маркетплейсов.

Файл:

```text
lab4_scraper/spiders/ecommerce.py
```

Для работы используется **Playwright**, поскольку страницы маркетплейсов динамически формируют содержимое и используют JavaScript.

Поддерживаются три источника:

1. **Wildberries**
2. **Ozon**
3. **Яндекс Маркет**

По умолчанию используется поисковый запрос:

```text
ноутбук
```

### Собираемые поля

Для каждого товара формируются:

- `title` — название товара;
- `normalized_title` — нормализованное название;
- `price` — цена;
- `rating` — рейтинг;
- `description` — описание/бренд;
- `url` — ссылка на товар;
- `source` — источник данных.

---

## 7. Работа с Wildberries

Для Wildberries используется поисковая страница:

```text
https://www.wildberries.ru/catalog/0/search.aspx
```

Поисковый запрос передаётся через параметр `search`.

Реализована последовательная пагинация страниц и сбор карточек товаров.

Пример запуска только Wildberries:

```powershell
python .\run_spider.py --spider ecommerce --category "ноутбук" --stores "wildberries" --max-items 100 --output .\output\wildberries.csv
```

---

## 8. Работа с Ozon

Для запроса `ноутбук` используется соответствующая категория Ozon и параметр поиска.

Перед переходом к результатам выполняется прогрев браузерной сессии:

1. открывается главная страница Ozon;
2. выполняется небольшая задержка;
3. выполняется прокрутка;
4. открывается страница результатов поиска;
5. ожидается появление карточек товаров.

После загрузки выполняются дополнительные прокрутки для получения товаров при ленивой загрузке страницы.

Пример запуска:

```powershell
python .\run_spider.py --spider ecommerce --category "ноутбук" --stores "ozon" --max-items 100 --output .\output\ozon.csv
```

---

## 9. Работа с Яндекс Маркетом

В проекте также реализована поддержка Яндекс Маркета.

Для него используются отдельные селекторы и JavaScript-обработка видимого содержимого страницы. Это необходимо из-за динамической структуры карточек и наличия большого количества служебного JSON/JavaScript-кода внутри HTML.

Перед извлечением данных выполняется несколько прокруток страницы, после чего Playwright получает видимый текст карточек.

Пример:

```powershell
python .\run_spider.py --spider ecommerce --category "ноутбук" --stores "yandexmarket" --max-items 100 --output .\output\yandex.csv
```

Также поддерживается сокращённый псевдоним:

```text
yandex
```

# 11. Нормализация рейтинга

Рейтинги разных маркетплейсов могут возвращаться с разными десятичными разделителями.

Например:

```text
Ozon       → 4.9
Wildberries → 4,9
```

При обработке значение приводится к единому виду:

```text
4,9
```

Таким образом, в итоговом CSV используется единый формат рейтинга.

# 12. Pipelines

В проекте реализованы три pipeline.

## CleaningPipeline

Файл:

```text
lab4_scraper/pipelines.py
```

Выполняет:

- исправление проблем с кодировкой через `ftfy.fix_text()`;
- удаление лишних пробелов;
- удаление переводов строк;
- `strip()`;
- формирование `normalized_title`.

Например:

```text
"  Ноутбук   ASUS  "
```

преобразуется в нормализованный вид:

```text
"Ноутбук ASUS"
```

а `normalized_title`:

```text
"ноутбук asus"
```

---

## DuplicationPipeline

Удаляет записи с повторяющимся URL в рамках одного запуска паука.

Используется множество `seen_urls`.

Если один и тот же URL встречается повторно, запись отбрасывается через `DropItem`.

---

## ValidationPipeline

Проверяет наличие обязательных полей:

```text
title
url
```

Если обязательное поле отсутствует, запись не попадает в итоговый результат.

---

# 13. Обработка ошибок и ограничение нагрузки

В `settings.py` настроен механизм повторных запросов Scrapy.

Повтор выполняется для HTTP-кодов:

```text
429
500
502
503
504
```

Количество повторных попыток:

```text
3
```

Для маркетплейсов дополнительно предусмотрены:

- ограничение количества параллельных запросов;
- задержка между запросами;
- случайная дополнительная задержка;
- последовательная обработка страниц одного источника;
- сохранение HTML при отсутствии товаров;
- логирование ошибок загрузки.

Для Ozon, Wildberries и Яндекс Маркета используется Playwright.

Проект **не выполняет автоматический обход CAPTCHA**. Если сайт показывает браузерную проверку, используется видимый браузер, в котором проверку при необходимости можно пройти вручную.

# 14. Командный интерфейс

Запуск всех пауков выполняется через:

```text
run_spider.py
```

Основные параметры:

| Параметр | Назначение |
|---|---|
| `--spider` | выбор паука: `news` или `ecommerce` |
| `--keywords` | ключевые слова для NewsSpider |
| `--days` | параметр периода для NewsSpider |
| `--category` | поисковый запрос для маркетплейсов |
| `--stores` | источники товаров |
| `--max-items` | максимальное количество записей |
| `--output` | путь к итоговому файлу |

Пример:

```powershell
python .\run_spider.py --spider ecommerce --category "ноутбук" --stores "wildberries,ozon" --max-items 110 --output .\output\marketplaces.csv
```

# 16. Проверка результатов

В проекте есть отдельный скрипт:

```text
verify_results.py
```

Он проверяет:

- количество записей;
- наличие обязательного `title`;
- наличие обязательного `url`;
- отсутствие дубликатов URL.

### Проверка JSON

```powershell
python .\verify_results.py .\output\news.json
```

### Проверка CSV

```powershell
python .\verify_results.py .\output\marketplaces.csv
```

По умолчанию требуется минимум 100 записей.

При необходимости минимальное количество можно изменить:

```powershell
python .\verify_results.py .\output\marketplaces.csv --min 50
```

# 19. Пример итогового CSV

Структура записи:

```text
title;normalized_title;price;rating;description;url;source
```

Пример:

```text
Ноутбук MacBook Neo 13 A18 Pro...;ноутбук macbook neo 13 a18 pro...;71 622 ₽;4,9;Apple;https://...;Wildberries
```

Таким образом, итоговый CSV можно непосредственно открыть в Excel и использовать для дальнейшего анализа.

### Отсутствующий рейтинг

Если у товара на маркетплейсе рейтинг отсутствует или не удалось получить его из карточки товара, значение `rating` **не заполняется искусственным значением**.

В Excel в такой ситуации соответствующая ячейка остаётся пустой:

```text
title;normalized_title;price;rating;description;url;source
Ноутбук ...;ноутбук ...;45 990 ₽;;...;https://...;Ozon
```

Это позволяет отличать товары без рейтинга от товаров, у которых рейтинг действительно указан.

# 20. Итог

В лабораторной работе разработана система сбора веб-данных на базе Scrapy и Playwright.

Система включает два паука:

- `NewsSpider` для сбора публикаций Habr;
- `EcommerceSpider` для сбора товаров с динамических маркетплейсов.

Для обработки данных реализованы очистка, нормализация, дедупликация и валидация. Для устойчивости системы предусмотрены повторные запросы при временных HTTP-ошибках, ограничение частоты запросов и журналирование.

`EcommerceSpider` дополнительно поддерживает работу с Wildberries, Ozon и Яндекс Маркетом, включая динамическую загрузку карточек товаров через Playwright.

Результаты сохраняются в JSON и CSV, причём CSV формируется с разделителем `;` и кодировкой `UTF-8-SIG`, что обеспечивает корректное открытие результатов в Excel.
